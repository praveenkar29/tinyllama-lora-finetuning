# Parameter-Efficient Fine-Tuning of TinyLlama with LoRA

This project fine-tunes [TinyLlama-1.1B-Chat](https://huggingface.co/TinyLlama/TinyLlama-1.1B-Chat-v1.0) on a 1,000-example subset of [Databricks Dolly 15K](https://huggingface.co/datasets/databricks/databricks-dolly-15k). It uses supervised fine-tuning and Low-Rank Adaptation (LoRA) to improve instruction following while updating only 0.1023% of the model parameters.

## Results

| Metric | Result |
|---|---:|
| Base model parameters | 1,100,048,384 |
| Trainable parameters | 1,126,400 |
| Trainable percentage | 0.1023% |
| Training examples | 1,000 |
| Optimizer steps | 63 |
| Average training loss | 1.8282 |
| Logged loss at step 10 | 2.1047 |
| Logged loss at step 60 | 1.7223 |
| Mean token accuracy | 0.6167 |
| Adapter weights | 4.31 MB |

The fine-tuned model followed the requested response format more closely on both qualitative test prompts. The evaluation is intentionally presented as a small demonstration rather than a comprehensive benchmark.

## Approach

1. Load TinyLlama in half precision with automatic device placement.
2. Convert Dolly records into user and assistant chat messages.
3. Add rank-8 LoRA adapters to the `q_proj` and `v_proj` attention modules.
4. Train for one epoch using gradient checkpointing and an effective batch size of 16.
5. Save only the adapter and tokenizer files.
6. Compare the base and fine-tuned responses using the same prompts and random seed.

## Run locally

### Requirements

- Python 3.10 or newer
- CUDA-compatible NVIDIA GPU
- Approximately 4 GB or more GPU memory

Create an environment and install the dependencies:

```bash
python -m venv .venv
```

On Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Start Jupyter and open the notebook:

```bash
jupyter lab
```

The first run downloads the TinyLlama model and Dolly dataset from Hugging Face. Model and dataset usage remain subject to their respective licenses and terms.

## Key implementation choices

- **Memory-aware batching:** a micro-batch of 1 with 16 gradient-accumulation steps provides an effective batch size of 16 on a 4 GB RTX 3050.
- **Parameter-efficient updates:** only the LoRA matrices are trainable; the original model weights remain frozen.
- **Automatic precision selection:** training uses bf16 when CUDA reports support and falls back to fp16 otherwise.
- **Reproducibility:** dataset shuffling and response sampling use a fixed seed of 42.

## Limitations

- The model was trained on only 1,000 examples for one epoch.
- The qualitative evaluation contains two prompts and does not establish general performance.
- Training loss covers the full formatted conversation, including the user prompt. An assistant-only objective could be evaluated in future work.
- Sampled generation can vary across library versions, CUDA versions, and hardware.

## Future improvements
